# 夹持增益残差策略：最小版设计审查

审查日期：2026-10-25。此文件记录实现合同与评估建议；单元测试通过不代表 PPO 已学会抓取，也不代表真实 XHand 的控制效果。

## 本版实验能回答什么

本版保留名义关节轨迹，只允许策略调整拇指、食指的两个夹持增益，各限制在 `[1, 2]`，每个策略步的变化不超过 `0.25`。物理为 300 Hz、触觉为 60 Hz、策略为 15 Hz。它用于验证触觉历史能否帮助选择夹持增益，而不能验证主动改变手形、接触位置、重抓或暂停抬升的能力。PD 刚度增益是可执行控制量，不等于经过标定的期望接触力。

每个策略周期包含 20 个物理步和 4 个新的触觉样本，采样落在第 5、10、15、20 个物理步末。模型在决策时只能读取已完成的采样；本周期末采到的数据只能影响下一周期。四帧覆盖 66.67 ms，并不自动代表模型已经具有较长时间记忆。

| preshape | 0.625 | 5.25 |

局部策略从 `floor(19.875 × 15) / 15 = 19.8666667 s` 接管。必须物理回放前缀到接管状态，并保留名义绝对时间；不能从初始场景直接写入接管关节姿态来冒充同一接触状态。缓存初始化状态时，需要保留物体、机器人、速度及相关物理状态；不同质量不能共用另一质量生成的接触前缀。

本版先按原始时间戳线性插值名义目标，再于 15 Hz 下零阶保持；这会保留名义时间进度，但与旧版 40 Hz 目标零阶保持不是同一离散控制输入。300 Hz 的积分步长也与旧实验不同。因此必须在新调度器下重新运行固定增益基线，不能把旧成功率直接当作新控制条件的基线。

最后一个完整策略周期结束于 `31.9333333 s`，比源轨迹末尾多 `58.333 ms`。末端目标可以保持，但任务有效保持时间仍只计算 `[28.875, 31.875]` 的区间交集。否则延长尾部会改变成功标准。

## 成功与奖励

旧测试成功要求指定最终 hold 的全部 120 个 40 Hz 样本均满足旋转后木块最低点离桌至少 5 cm，且没有故障。它检查指定 3 秒保持区间内的全部采样，而不是若干次抬升时长累计达到 3 秒。新实现的物理指标以 60 Hz 记录，并按真实时间求保持区间交集；任一纳入保持评估的采样不满足高度，就不能用其他时刻补偿。该检查不声称覆盖每个 300 Hz 物理状态之间的全部瞬间。

训练奖励可利用仿真物理标签，但 actor 观测不能包含木块真值位置、质量、摩擦或物理接触滑速。高度收益必须以有效双指物体接触为前提，防止空手、弹起物体或仍在桌上获得抬升收益。单元测试检查无接触、单指接触及未离桌场景没有正的高度收益。

仅有高度和持续时间的成功函数不证明物体一直被双指抓持。环境另行维护 `hold_contact_ok`，要求整个保持阶段各评估采样中均有至少两个带触觉指节的物理接触。这个支持要求比旧版仅检查高度更严格，所有新基线都应采用相同标准。当前它检查任意两个带触觉的指节，并没有将成功限定为拇指和食指。评估还应记录最终接触状态与桌面/其它支撑接触，不能静默更换旧成功率的定义。

奖励中的接触载荷是接触力模长的求和代理量，不能直接当成真实法向夹持力。增益代价与实际载荷代价也不应混为一谈。各奖励项按真实经过时间积分，超时是 episode 结束原因，不是成功证据。

## 独立评估分组

以下为建议，不表示已经完成训练或统计验证。所有组使用相同材料参数、前缀生成方式、初始状态及采样频率，按 episode 配对比较。

| 组别 | 作用 |
| --- | --- |
| 固定增益 1.0 | 新时钟下的原始夹持基线 |
| 固定增益 2.0 | 检查学习策略是否仅等同于始终加力 |
| 固定增益 1.5（可选） | 判断动作中点是否本身已足够 |
| 训练后的 PPO，真实触觉 | 被评估策略 |
| 独立重新训练的无触觉 PPO | 检查是否仅靠阶段、关节和时间进度选择增益 |
| 评估时触觉置零或打乱（诊断） | 检查触觉依赖；分布偏移测试，不能替代无触觉重训练对照 |

首次训练的八个环境若只在初始化时分配质量，它们仍只有八种质量条件；重复 reset 不会增加质量覆盖。将这一限制写入运行配置。首先在未参加梯度更新的质量与摩擦组合上评估，再讨论是否扩大随机化；留出集不能用于挑选每次训练的最佳 checkpoint。初始位置变化应单独分组，避免混淆“夹持强度适应”与“名义轨迹已不再能对准物体”。

每组至少报告逐 episode 的成功、保持最低高度、双指支持时长、实际接触载荷积分与峰值、增益轨迹、故障、终止原因。先做流程冒烟检查，再增加独立随机种子；少量固定场景中的成功不能作为泛化结论。

## 现阶段仍存在的限制

- 仿真触觉的剪切信号由相对速度项构造。后续应加入仅法向输入、完整输入、噪声/延迟变化的消融，并用真实触觉检验。
- 只调整两个增益时，低摩擦条件可能超出动作能力。失败不自动说明触觉编码器不足。
- 这版不要求单独训练滑动风险头，也没有证明主动试探已经出现。它先验证直接的任务策略闭环。
- 单元测试覆盖纯时钟、插值、边界约束及奖励合同；真实场景的重置一致性、接触判据和有效闭环频率还需要仿真日志验证。

## reset 与触觉历史隔离复核

代码中 `prefix_history` 在物理前缀结束后通过 `.copy()` 保存；每次 reset 用切片赋值将 `history` 恢复为该缓存，并清除待执行动作、增益的 Python 记录和累计统计。`_obs()` 与 `terminal_observation` 都返回触觉数组副本，当前时序卷积网络没有跨调用的循环隐状态。此前的审查未发现显式将上一轮末尾触觉带入新 episode 的路径，但这只覆盖 Python 历史隔离，不能证明底层物理过程可重复。

后续物理复测发现：精简 `SimState/get_state()` 的恢复不足以保证相同动作产生相同后续轨迹。即使只打开 Genesis 确定性算法选择，在 nominal→strong→nominal 的八 lane 测试中，前后 nominal 的最大高度差仍为 `0.0375226736 m`。这项结果来自 `outputs/residual_rl_20261025/determinism_probe/result.json`，表明仅靠算法开关不能完成重复性修复。

同样打开确定性算法，并改用官方完整 `SceneCheckpoint` 后，`outputs/residual_rl_20261025/determinism_full_checkpoint_probe/result.json` 记录：nominal→strong→nominal 三次运行分别为 `2/8、8/8、2/8`，两次 nominal 在所记录的全部高度与逐指接触载荷上最大差均为 **0**。这验证了本次配置下的完整恢复能够消除观测到的物理分歧；没有逐项定位究竟是哪一个求解器缓存导致了旧差异，也不把有限复测推广为所有仿真配置的确定性保证。

当前环境在物理前缀结束后保存 `prefix_checkpoint = scene.__getstate__()`，reset 在同一场景上调用 `scene.__setstate__(prefix_checkpoint)`。质量、惯量、PD参数、控制目标、接触缓存和仿真时钟随完整检查点一起恢复，之后不再额外补写质量或增益，也不前进物理步。Python 触觉历史单独恢复；从新 episode 的第一个动作开始才按策略更新增益和目标。

CPU fixture 测试同步改为执行完整检查点恢复路径，不初始化 Genesis：旧 episode 的哨兵历史被清除；追加四帧不会修改缓存前缀；终止观测与新观测互不共享可写历史；reset 仅恢复检查点，不再写材料、PD增益或控制目标，不推进物理时间。自动 reset 还检查一个普通策略周期仅有20次物理步、1次动作增益更新和1次目标更新。加上原有测试，共 **26项通过**。这些测试验证调用合同，物理重复性的证据来自上述独立仿真复测。

修复前 `suite_mixed`、`suite_200g` 的结果仍保留为 `repeatability_failed` 调试记录；新检查点复测不会追溯性地使旧配对评估变为有效。正式比较应在修复后的恢复方式下重新运行并保存独立结果。

## 初始模型 CPU 推理耗时

对 `outputs/residual_rl_20261025/ppo_tactile_seed0/initial_model.zip` 做单环境 CPU 基准，模型共 123,173 个参数，PyTorch 使用 4 线程。checkpoint SHA256：`7e47e7bbb84869da13b73fe98634ae47ea5a09afe666e2ebbe6cd8a9c97388e0`。每种输入先热身 200 次并排除，再测 1,000 次确定性 `PPO.predict()`。

| 合成输入 | p50 | p95 | p99 | 最大值 |
| --- | ---: | ---: | ---: | ---: |
| 触觉和状态全零 | 0.194 ms | 0.211 ms | 0.259 ms | 0.353 ms |
| 触觉三轴高斯值，标准差 0.1 nominal N；状态为零 | 0.427 ms | 0.562 ms | 0.618 ms | 0.756 ms |

该时间包含 NumPy 输入转张量、网络执行和动作返回，不包含触觉采集、通信、执行器和物理仿真。测试过程中可能存在其他训练任务的 CPU 竞争；结果是一次本机计算耗时测量，不是最坏时延保证。随机三轴输入只用于运行计算路径，并不声称是物理合理的接触分布。这项结果说明当前网络计算量相对 15 Hz 的 66.67 ms 周期较小，不说明完整机器人闭环已达到该频率，也不说明初始模型有抓取能力。
