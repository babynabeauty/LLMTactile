# Tactile Genesis × Astra 接入验证报告

## 结论

本机 RTX 5090 已运行 Wuji 单环境手内立方体姿态调整任务。当前 Codex 对话中的 Astra 实际逐轮读取场景图片、触觉摘要和关节状态，并通过命令行输出关节位置动作；没有调用独立模型 API，没有训练 runner、教师 checkpoint 或预录动作序列。

接口闭环跑通，但本次策略演示**未完成目标姿态**。这是一次工程接入验证，不能作为统计充分的能力 benchmark，也不能证明实时控制能力或对任意手型的泛化能力。

## 实际 Astra 演示

| 指标 | 结果 |
| --- | --- |
| 种子 / 回合 | 42 / 1 个回合 |
| 实际模型决策数 | 30 |
| 控制步数 / 仿真时长 | 132 / 3.3 秒 |
| 目标达成事件 | 0 |
| 初始姿态误差 | 120.91° |
| 最小姿态误差 | 111.97° |
| 最终姿态误差 | 117.02° |
| 掉落 / 超时 | 均未发生；达到决策上限后主动停止 |
| 累计决策等待 | 340.67 秒 |
| 每次等待均值 / 中位数 | 11.36 / 11.49 秒 |
| 等待范围 | 6.53–18.13 秒 |
| 图像与触觉记录 | 133 个状态，包含初始状态 |

等待时间包含模型思考、工具调度、图片查看和对话停顿，并非模型 API 推理延迟。仿真仅在 `step` 请求内前进。原速视频为 40 FPS，包含初始帧，因此媒体时长为 3.325 秒；慢放版约 26.575 秒。

动作过程中建立了多指接触，并使立方体出现可见转动；后来立方体主要由掌部支撑，重新抓握没有实现目标姿态。触觉可能包含自接触，因此不能仅凭激活数量声称已成功抓握物体。未掉落仅适用于本次 3.3 秒观察窗口，不代表完成了完整 20 秒回合。

控制期间没有读取物体姿态、真实误差、奖励或内部成功评分；上述误差在第 30 次决策结束、服务关闭后才从评估日志计算。每次动作都带有基于当轮反馈的 `note`，动作前后完整接口观测和等待时间均在 `interaction.jsonl` 中。

### 演示版本与交付版本的差异

事后审计发现，上游 `last` 选择历史索引 -1，而 Genesis 历史实际上按新到旧排列。因此首轮演示读取的触觉摘要相对场景滞后 **0.020 秒**。这是真实反馈控制，但不是完全同步的视觉触觉输入。完整五帧六维数据均已保留；交付版已改为索引 0，且新增摘要与最新完整数组的一致性检查。没有改写首轮演示日志或重放动作来替换演示。

交付版另增加每控制步写入 `tactile_stream.npy`，减少进程异常退出时丢失原始触觉的风险。首轮演示的完整触觉在正常关闭时保存到 `tactile.npz`。后续版本的日志和演示日志用各自 manifest 源码哈希区分。

## 基础验证

已完成 1,000 控制步的独立脚本测试，标签明确为 `scripted_smoke`，与上述 Astra 演示分开。覆盖：

- GPU 运算、关节动作索引和实际响应、有限观测、图片输出。
- 无接触与有接触的不同读数、全部六个分量、每区域布局数量。
- 等待期间时间不变、动作推进时长正确、非法请求不推进仿真。
- 第 800 步超时终止后禁止继续动作，终止观测保存，显式重置后运行剩余 200 步。
- 每步触觉流与最终 NPZ 逐元素一致；最终版另外核对摘要使用最新子步。

最终验证结果保存在 `outputs/astra_bridge/smoke_verified/smoke_test.json`；四项快速单元测试通过，216 个已安装包的依赖一致性检查通过。录像已检查为 H.264、768×640、40 FPS，并实际查看了演示的初始帧和每次决策后的场景帧。
